# 61. grep이 벡터 검색을 이겼다는 논문 읽기

> C3 · 문서가 수십만 개일 때 — 끌어와서 grep · 수업 61 / 66 · [전체 목록](../../README.md#수업-목록)

## 이 수업에서 하는 것

- DCI 논문은 검색 도구를 쓰는 에이전트와 셸 명령(grep)을 쓰는 에이전트를 비교했고, 830문항에서 80.0퍼센트 대 69.0퍼센트로 grep 쪽이 앞섰다고 해요.
- grep을 쓰는 에이전트는 정확한 낱말 찾기, 조건 결합, 앞뒤 문맥 읽기에 강해요. 다만 우리 앞선 실험(23 대 23)과는 자료·질문·모델·비교 상대가 모두 달랐어요.
- 에이전트의 실패는 문서를 못 찾은 경우와, 찾고도 필요한 줄을 못 읽은 경우로 나눠서 봐요.

## 실행

먼저 문서 묶음을 받습니다 (이미 받았다면 건너뜁니다): [C3 자료 받기](../../c3/README.md)

## 과제

실습 저장소에 준비된 「검색만」 실행 로그 두 개를 차례로 읽어 보세요. 하나는 래퍼 질문 로그([로그 A](../../c3/logs/A-래퍼-검색만.md))이고, 다른 하나는 초등학교 질문 로그([로그 B](../../c3/logs/B-초등학교-검색만.md))예요. 두 로그가 각각 어느 종류의 실패(근거 문서를 못 찾음 / 문서는 찾았는데 필요한 줄을 못 읽음)에 해당하는지 표시해 보세요.

## 풀이

<details><summary>풀이 보기</summary>

로그에는 검색어마다 돌려받은 발췌가 그대로 적혀 있어요.

**로그 A는 첫째 실패(근거 문서를 못 찾음)예요.** 진주시 초대 시장을 묻는 실행 기록이에요. 발췌에 뜬 문서 제목을 훑어보면 넋업샨과 한국국제대학교는 보이지만 진주시는 없어요.

**로그 B는 둘째 실패(문서는 찾았는데 필요한 줄을 못 읽음)예요.** 대구 도원동의 공립 초등학교 제1회 졸업생 수를 묻는 기록이에요.

- 도원동의 세 학교 문서는 모두 발췌에 떴고, 가장 먼저 개교한 대구대곡초등학교도 두 번 떴어요.
- 이 문서는 전체가 1,583자인데, 발췌는 두 번 모두 350자부터 1,050자까지의 구간이었어요.
- 그 구간에서 처음 나오는 졸업 기록은 제4회, 졸업생 314명이에요. 제1회 졸업과 졸업생 116명은 그 앞쪽에 적혀 있어서, 필요한 줄이 발췌에 한 번도 들어오지 않았어요.

겉으로는 둘 다 못 맞힌 결과지만 고쳐야 할 지점은 서로 달라요. 앞의 실패는 찾는 쪽을 손봐야 하고, 뒤의 실패는 문서를 읽는 쪽을 고쳐야 해요.

</details>
