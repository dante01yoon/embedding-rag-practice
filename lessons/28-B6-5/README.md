# 28. 맥락 검색 (contextual retrieval)

> B6 · 검색 개선 · 수업 28 / 60 · [전체 목록](../../README.md#수업-목록)

## 이 수업에서 하는 것

- 맥락 검색은 LLM이 청크마다 문서 속 맥락을 한두 문장 써서 붙이고 색인해요. 제목만 붙이는 싼 방법은 우리 데이터에서는 오히려 떨어졌어요.
- LLM 맥락은 긴 질문에서는 효과가 작았고, 542만 토큰이 들었어요. 이미 점수가 높으면 올라갈 자리가 적어요. 늘 비용과 효과를 같이 재요.
- 이유를 다시 볼게요. 청크는 잘려 나오면서 무엇에 대한 글인지 말해 주는 단어를 잃어요. 맥락 문장이 그 단어를 돌려줘서 BM25와 벡터가 찾기 쉬워져요. 그래서 질문이 짧고, 청크에 없는 단어로 물을수록 효과가 커요. 비용은 인덱스를 만들 때 한 번이에요.

## 과제

질의 변환 수업에서 만든 짧은 질문 파일로 바꿔서, 같은 여섯 줄 성적표를 다시 매겨 보세요. 맥락의 효과가 어떻게 달라지는지 보세요.

## 풀이

<details><summary>풀이 보기</summary>

골든셋을 읽는 줄에서 파일 이름만 짧은 질문 파일로 바꿔요.
짧은 질문에서는 그대로의 점수가 확 내려왔어요. 벡터는 0.82에서 맥락을 붙이니 0.87, BM25도 0.82에서 0.87, 하이브리드는 0.74에서 0.79로 세 줄 모두 올랐어요.
벡터의 10위 안 실패는 6개에서 3개로 반이 됐어요. 올라갈 자리가 있으니 맥락이 일을 한 거예요. 기법의 효과는 데이터와 질문 모양에 따라 달라져요. 그래서 내 질문으로 재요.

영상에서 입력한 그대로입니다.

- `b6/ctx_search.py`를 엽니다.
- 15행으로 갑니다.
- 그 자리의 줄 1개를 지웁니다.

```python
qa = json.load(open("k8s/qa_ko_short.json"))  # 검색창처럼 짧게 줄인 질문
```

- 실행: `uv run python b6/ctx_search.py`
