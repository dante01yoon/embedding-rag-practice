# 64. pull 만들기: 끌어와서 뒤지기

> C3 · 문서가 수십만 개일 때 — 끌어와서 grep · 수업 64 / 66 · [전체 목록](../../README.md#수업-목록)

## 이 수업에서 하는 것

- 문서가 수십만 개일 때는 BM25 색인(SQLite FTS5)을 디스크에 두고, pull 도구가 검색 순위 상위 문서만 작업 폴더로 가져와요.
- find와 read는 작업 폴더에 들어온 문서에만 쓸 수 있어요. 문서를 읽어 새 단서가 생기면 그 이름으로 다시 pull을 불러요.
- 사서(검색기)가 순위 안에 못 올린 문서는 탐정(에이전트)도 끝내 볼 수 없어요.

## 실행

먼저 문서 묶음을 받고 (이미 받았다면 건너뜁니다): [C3 자료 받기](../../c3/README.md)

`find`는 `rg`(ripgrep)를 부릅니다. 설치돼 있는지 확인합니다.

```bash
rg --version
```

수업 명령 ① 1만 개 묶음의 색인 만들기.

```bash
uv run python c3/build_index.py 10k
```

- `wiki/docs.db` 안에 `fts_10k` 표가 생깁니다. 1만 개 묶음은 10초쯤 걸립니다(강사 화면 8초).
- 10만 개 묶음을 받았다면 `uv run python c3/build_index.py 100k`도 실행합니다(강사 기기에서 75초). 약 65만 개 전체 묶음은 약 8분이 걸리고, 강사 화면으로만 봅니다.
- 색인을 만들지 않고 `pull`을 부르면 `no such table: fts_10k` 오류가 납니다.

수업 명령 ② pull로 끌어온 문서만 읽히는지 보기. 파이썬 창(`>>>`)이 열리면 한 줄씩 입력합니다.

```bash
uv run python -i c3/try_tools.py 10k pull
```

```python
read("w461996")
pull("한국국제대학교 폐교", k=50)
read("w461996")
exit()
```

첫 `read`는 작업 폴더에 문서가 없어서 `out_of_scope`가 나오고, `pull`로 50개를 가져온 뒤에는 같은 `read`가 `ok`로 읽힙니다.

수업 명령 ③ 에이전트가 약 65만 개 묶음에서 질문을 푼 강사의 기록 보기.

```bash
uv run python c3/show.py pull    # 래퍼 질문 · pull을 네 번
uv run python c3/show.py miss    # 라이트 노벨 질문 · 근거 문서가 끝내 안 들어온 실행
```

저장소 맨 위 폴더에서 실행합니다. 여기까지는 모델을 부르지 않으니 **OpenRouter 키가 필요 없고** 비용도 들지 않습니다.

## 과제

래퍼와 초대 시장 질문(질문 id `h02`) 하나만 골라서 pull 개수를 바꿔 돌려 보세요. 개수를 고정해 주는 `c3/pull_k.py`에 질문 id와 개수 20을 넘겨 한 번, 300을 넘겨 한 번 돌리고, 두 실행의 도구 호출 수를 비교해 보세요.

```bash
uv run python c3/pull_k.py h02 20 10k
uv run python c3/pull_k.py h02 300 10k
```

- **OpenRouter 키 필요.** 모델을 부릅니다. 질문 하나만 실행하므로 한 번에 약 0.01~0.02달러입니다(강사 기록: 20개 고정 0.016~0.022달러, 300개 고정 0.007~0.010달러).
- 끝의 `10k`는 받은 묶음 이름입니다. 빼면 전체 묶음(`all`)을 찾습니다. 색인(수업 명령 ①)을 먼저 만들어 두어야 합니다.
- 강사 기록은 약 65만 개 묶음에서 잰 것이라, 1만 개 묶음에서는 숫자가 다르게 나옵니다.

## 풀이

<details><summary>풀이 보기</summary>

강사가 약 65만 개 묶음에서 개수마다 세 번씩 돌린 기록이에요.

| 한 번에 | 끝난 상태 | 도구 호출 | 끝났을 때 작업 폴더 |
|---|---|---|---|
| 20개 고정 | 세 번 모두 턴 한도(20번)에 걸려 답을 못 냄 | 22~27번 | 98~124개 |
| 300개 고정 | 세 번 모두 정답 | 11~15번 | 923~1,119개 |

다만 같은 300개로 한 번 더 돌렸을 때는 턴 한도에 걸렸어요. 같은 조건에서도 실행마다 흔들린다는 걸 기억해 두세요.

어려운 여덟 문항 전체로 넓히면 이래요.

| 한 번에 | 맞은 수 (8문항) | 질문 하나의 입력 토큰 |
|---|---|---|
| 20개 고정 | 5~6개 | 약 9만 7천 개 |
| 100개 고정 | 6~7개 | 약 5만 4천~8만 4천 개 |
| 300개 고정 | 7~8개 | 약 4만 7천~5만 3천 개 |

적게 가져오면 필요한 문서를 다시 가져오느라 턴을 쓰고 입력 토큰도 더 쌓여요. 가져오는 일은 싸고 읽는 일이 비싸기 때문에 한 번에 넉넉히 가져오는 편이 유리해요. 다만 평가 문항이 여덟 개뿐이라 한 문항 차이가 크게 보일 수 있어요.

강사 기록의 표 전체는 키 없이 볼 수 있어요. 「끌어오는 개수 고정」 표를 보세요.

```bash
uv run python c3/report.py
```
