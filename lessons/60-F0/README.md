# 60. 통합 프로젝트 미리보기 — 전·월세 상담 챗봇 설계 (업데이트 예정)

> F · 통합 프로젝트 (업데이트 예정) · 수업 60 / 60 · [전체 목록](../../README.md#수업-목록)

## 이 수업에서 하는 것

- 지금까지 만든 조각(하이브리드 검색·리랭킹, 근거 없으면 거절, 텍스트→SQL, 골든셋 평가, 캐시, 권한, 트레이스)을 하나의 서비스로 묶어요. 주제는 **전·월세 상담 챗봇**이에요.
- 전입신고, 확정일자, 보증금 돌려받기 같은 질문에 법령과 공공기관 안내를 근거로 답해요. 상관없는 질문이나 답하면 안 되는 질문에는 답하지 않아요.
- 손에 남는 것: `docker compose up` 한 줄로 뜨는 챗봇, 시스템 설계도, 거절 정확도까지 담은 평가 리포트.

### 근거 자료 (모두 공개 자료)

| 자료 | 넣는 방식 |
|---|---|
| 국토교통부 전월세 실거래가 | 표 (SQL로 조회) |
| 주택임대차보호법 등 법령 | 청크 → 벡터 |
| 법제처 생활법령정보 주택임대차 안내 | 청크 → 벡터 |

답마다 출처와 기준일을 붙여요.

### 시스템 구성

- **web**: 채팅 화면(프론트엔드 스캐폴드 제공). 근거 번호·출처 카드, 실거래가 표 카드
- **api**: FastAPI 서버
- **cache**: Redis, 같은 질문이면 바로 답을 꺼내요
- **db**: Postgres + pgvector, 법령·안내문 청크와 실거래가 표
- **worker**: 매일 공공 데이터를 확인해, 새 실거래 기록과 바뀐 조문만 db에 넣어요
- LLM은 OpenRouter로 불러요. 요청마다 트레이스를 남기고, GitHub Actions 평가 게이트가 골든셋 점수가 떨어지면 배포를 막아요.

### 질문 하나가 지나가는 길

1. 캐시 확인 → 있으면 바로 답
2. 질문 분류: 문서 질문 / 숫자 질문 / 거절할 질문
3. 문서 질문: 하이브리드 검색 후보 20개 → 리랭커가 4개 → 근거 점수가 문턱보다 낮으면 "자료에 없다"고 답
4. 숫자 질문: 텍스트→SQL로 실거래가 표 조회(읽기 전용 계정)
5. 거절할 질문(개별 계약 판단, 투자, 개인정보, 주제 밖): 정해진 문장으로 거절하고 대한법률구조공단·주택임대차분쟁조정위원회 같은 공식 창구 안내
6. 답 전송 → 캐시 저장 → 경로·시간·비용 트레이스

### 일곱 단계 (다음 업데이트)

뼈대 → 수집 → 문서 답 → 길 나누기 → 평가(문서·숫자·거절 세 묶음 골든셋) → 운영(캐시·트레이스) → 안전(관리자 권한·인젝션 검사)
