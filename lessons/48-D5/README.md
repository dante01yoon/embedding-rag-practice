# 48. 로그와 트레이스 · 일어난 일을 나중에 찾기

> PART D · 운영 · 수업 48 / 60 · [전체 목록](../../README.md#수업-목록)

## 이 수업에서 하는 것

- 요청마다 트레이스를 남기고, 검색과 LLM을 스팬으로 나눠 시간과 결과를 적었어요.
- 로그로 거절한 질문은 검색부터 약했다는 걸 찾았고, 답을 그대로 적으면 암호 12개가 새는 것도 찾았어요. 가린 뒤에는 0개였어요.
- 왜 트레이스냐면, 틀린 답이 검색 때문인지 LLM 때문인지 단계별로 나눠 봐야 고칠 곳이 보이기 때문이에요. 1위 점수가 0.6보다 낮으면 절반을 거절했죠.

## 과제

로그에서 1위 점수가 가장 낮은 질문 세 개를 뽑아 보세요. 그 질문들은 어떻게 답했을까요?

## 풀이

<details><summary>풀이 보기</summary>

로그를 1위 점수로 정렬해서 앞의 세 개를 출력해요.
점수 0.55, 0.55, 0.56인 질문들이에요. 그런데 셋 다 거절하지 않고 답을 했어요.
근거가 약한데 자신 있게 답한 질문이에요. 이런 질문을 로그에서 골라 사람이 먼저 확인하면, 틀린 답을 빨리 찾을 수 있어요.

영상에서 입력한 그대로입니다.

- `d5/trace.py`를 엽니다.
- 71행으로 갑니다.

```python
for x in sorted(logs, key=lambda x: x["search"]["score"])[:3]:  # 1위 점수가 가장 낮은 질문 = 검색이 헤맨 질문
    print(f"  점수 {x['search']['score']:.2f} | {x['q'][:28]} → {x['llm']['answer'][:20]}")
```

- 실행: `uv run python d5/trace.py`

</details>
