# 30. 에이전트 청킹 · LLM이 읽고 경계를 정하면

> B6 · 검색 개선 · 수업 30 / 60 · [전체 목록](../../README.md#수업-목록)

## 이 수업에서 하는 것

- 에이전트 청킹은 LLM이 번호 붙인 문장을 읽고 새 묶음이 시작되는 번호를 고르는 방법이에요.
- 크게 자르면 50.0퍼센트, 작게 부탁하면 66.2퍼센트였지만 재귀의 76.2퍼센트에는 못 미쳤고, 색인마다 92만 토큰이 들었어요.
- 이유도 같이 기억해 두세요. 번호만 받아서 지어내기와 출력 비용을 막았고, 답은 정규식으로 걸러서 형식이 어긋나도 버텼어요. 그래도 크게 자르면 2,000자 예산에 몇 개 안 들어가고, 표처럼 문장으로 안 나뉘는 덩어리는 LLM도 못 나눠요.

## 과제

500자까지 부탁했는데, 실제로 500자를 넘긴 청크는 몇 개일까요? 가장 긴 청크는 몇 자일까요?

## 풀이

<details><summary>풀이 보기</summary>

500자를 넘는 청크를 모아서 개수와 비율, 가장 긴 길이를 출력해요.
2,037개 중 1,002개, 49퍼센트가 500자를 넘었어요. 가장 긴 청크는 3,456자예요. 부탁한 크기의 일곱 배 가까이 돼요.
LLM은 주제를 따라 판단하다 보니 크기 부탁을 자주 넘겨요. 그래서 실무에서는 LLM이 정한 경계에, 최대 길이를 코드로 한 번 더 자르는 규칙을 덧붙여요.

영상에서 입력한 그대로입니다.

- `b3x/agent_cut.py`를 엽니다.
- 60행으로 갑니다.

```python
over = [len(u) for u in units if len(u) > 500]  # 부탁한 500자를 넘긴 청크
print(f"500자 넘는 청크 {len(over)}개 ({len(over) / len(units) * 100:.0f}%) · 가장 긴 청크 {max(len(u) for u in units):,}자")
```

- 실행: `uv run python b3x/agent_cut.py`

</details>
